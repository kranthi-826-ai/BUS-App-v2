# Data Model

All primary keys are UUID/ULID-style identifiers generated by the application. Store timestamps in UTC. Every mutable authoritative table has `created_at`, `updated_at`, and optimistic versioning where concurrent edits matter.

## Core tables

- `colleges`: name, code, timezone, active.
- `users`: college, external/student/staff ID, name, email/phone as approved, password hash, role, status.
- `refresh_tokens`: user, token hash, family, expiry, rotated/revoked timestamps.
- `buses`: college, registration number, display name, capacity, active.
- `routes`: college, name, direction, active.
- `stops`: college, name, latitude, longitude, active.
- `route_stops`: route, stop, sequence, scheduled offset; unique route+sequence and route+stop.
- `bus_route_assignments`: bus, route, valid date range.
- `incharge_assignments`: user, bus, valid date range.
- `bus_codes`: bus, code hash, expiry, max uses, use count, revoked timestamp.
- `student_enrolments`: student, bus, selected stop, status; one active enrolment per student in MVP.
- `trips`: bus, route, in-charge, started/ended timestamps, status; enforce one active trip per bus.
- `location_points`: trip, device, sequence, captured/received time, coordinates, accuracy/speed/heading; unique trip+device+sequence.
- `latest_bus_locations`: one row per active trip for efficient reads.
- `alert_subscriptions`: student, bus, stop, radius, enabled, push token reference.
- `alert_states`: subscription, trip, state, last distance, notified/rearmed timestamps; unique subscription+trip.
- `push_devices`: user, installation ID, encrypted/token value, platform, last seen, revoked.
- `notification_outbox`: event ID, recipient/device, payload, state, attempts, next attempt.
- `audit_events`: actor, action, resource type/ID, correlation ID, timestamp, non-sensitive metadata.

## Retention

- Latest location: current projection only.
- Raw location points: default 30 days, then delete or irreversibly aggregate after college approval.
- Auth/audit records: default 180 days; college policy wins.
- Push tokens: remove on logout/unregistered receipt/inactivity.
- Never store student continuous GPS.

## Phase 2/3

- `attendance_records`: trip, student, status, source (`MANUAL`, `FACE`), marked by, evidence reference, confidence nullable, timestamp; unique trip+student.
- Biometric templates/images must live outside the core database with separate encryption, consent, access, and deletion controls. They are not created in MVP.

Flyway migrations are append-only after release. Tests must verify foreign keys, uniqueness, active-trip race handling, deletion/retention, and rollback/restore behaviour.
